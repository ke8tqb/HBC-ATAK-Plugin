1. Overview

HBC Radio is an ATAK plugin that transmits Cursor-on-Target (CoT) situational-awareness data between EUDs over amateur-radio audio links, with no network infrastructure. The stack has three interfaces, each specified in this document:

  • Physical layer — one of three selectable audio modems (AFSK1200, OFDM COFDMTV, or Mercury HF / FreeDV DATAC4) carrying opaque byte frames over a voice radio.
  • Mesh network layer — an uncoordinated distance-vector routing protocol (announce propagation, hop-by-hop directs, end-to-end ACKs) adapted from the Reticulum routing model for unencrypted FCC Part 97 operation.
  • Application layer — the HBC Protocol v1.6, a compact bit-packed binary encoding of CoT events (PLI, markers, chat, alerts, shapes, CASEVAC).
NOTE: All content is transmitted in cleartext. Callsigns ride in every frame header, satisfying station-identification requirements.

2. System Architecture

Data path for one transmission:

ATAK CoT event → HBC encoder (binary payload) → MeshRouter (13+ byte header, routing) → modem framing → audio → radio (VOX or PTT)

Reception is the mirror image. The mesh layer decides whether a received frame is delivered locally, forwarded toward its destination, rebroadcast (announces), or dropped.

3.1 AFSK1200 / AX.25

Mesh frames are carried as the information field of a single AX.25 UI frame. The AX.25 addresses are fixed PHY framing only and are not used for routing: destination HBC, source = operator ham callsign (Part 97 ID), no digipeater path. TX renders the entire burst in advance: lead silence (150 ms), optional VOX leader tone, HDLC flag preamble (“TX Dwell”, default 500 ms), frame, tail silence (250 ms).

3.2 OFDM COFDMTV (rattlegram)

Payload framing inside the 170-byte OFDM block: byte 0 = mesh frame length (1–169), bytes 1..n = mesh frame, zero-padded. The operator callsign also rides in the OFDM metadata header. Carrier 1500 Hz; VOX leader implemented as noise symbols (~180 ms each).

3.3 Mercury HF (FreeDV DATAC4)

Burst layout matches the Mercury HF modem exactly: preamble → one DATAC4 frame with CRC-16 in the final two bytes → postamble, with 100 ms head/tail silence. Payload framing inside the 54-byte usable frame: byte 0 = length, byte 1 = 'H' domain marker, bytes 2..n = mesh frame, zero-padded.

NOTE: This interface speaks Mercury’s waveform/frame/CRC layout, not Mercury’s ARQ data-link protocol. Desktop Mercury demodulates these frames but does not route them to its TCP interface.

3.4 Channel Access (CSMA)

Every modem performs carrier-sense multiple access before transmitting: RX audio energy is tracked against an adaptive noise floor (busy above 4× floor, held 400 ms past the last loud chunk). Before TX the station waits for a clear channel plus a random 150–550 ms backoff that must remain clear; after 8 s (15 s on Mercury) the frame is sent regardless so traffic cannot be starved. AFSK additionally uses the demodulator’s DCD as a second carrier-sense input.

4. Mesh Network Layer

Implements “Adaptation of Uncoordinated Distance-Vector Routing for Unencrypted Amateur Radio Networks” (see References), with one approved deviation: packet payloads carry HBC binary rather than ITA2 text.

4.2 Callsign Encoding (ITA2, 5 bytes)

Callsign fields are exactly 8 five-bit ITA2 codes bit-packed MSB-first into 5 bytes (40 bits), NULL (00000) padded. Shifts: LTRS = 11111, FIGS = 11011. A leading LTRS is emitted before the first letter; when a callsign would need 9 codes (e.g. KE8TQB), the leading LTRS is omitted — decoders start in letters state, so both forms decode identically.

NOTE: The source paper’s K1ABC example lists byte 03 as BF, but its own bit-level breakdown evaluates to DF; this implementation follows the arithmetic. All vectors above are enforced by the automated test suite (codec-test/MeshRouterTest.java).

A station whose callsign matches Next Hop looks the destination up in its routing table, rewrites Next Hop and Transmitter, and re-transmits. The final destination delivers the payload and returns an ACK. With no route, the packet is dropped (relays) or sent as a Broadcast fallback (originator).

Intermediate stations forward ACKs toward the destination when a route is known; the dedup cache prevents forwarding storms.

4.7 Route Discovery and Maintenance

  • Announce propagation — unseen announces are rebroadcast with hops+1 and the local callsign as Transmitter; receivers record Destination = Origin, Next hop = Transmitter. Lowest hop count wins; equal-cost ties resolve “first heard.”
  • Passive learning — hearing any valid frame registers its Transmitter as a 0-hop neighbor and (for non-announce frames) the Origin as reachable via that Transmitter. A single received PLI is sufficient to make a station addressable.
  • Announce-on-traffic — a station’s own transmissions serve as its announce; an explicit Announce is sent only after 10 minutes with no transmissions (keepalive).
  • Expiration — routing entries expire 30 minutes after the last frame that refreshed them; cleanup runs every 60 s.

4.8 Loop Prevention

Receivers cache [Origin + Sequence ID + Type] signatures for 5 minutes. A packet whose signature is cached is silently discarded (except a duplicate Direct addressed to this station, which is re-ACKed without re-delivery to survive a lost ACK).

4.9 Reliability and Retries

Directs operate fire-and-wait: the originator starts a retry timer of 5 s plus 0–2 s random jitter. If no ACK arrives, the Direct is re-transmitted with the same Sequence ID, up to 3 retries, after which the transmission is declared failed (logged). Broadcasts are never acknowledged or retried.

5. Application Layer (HBC Protocol v1.6)

5.4 Direct-Message Tags and Receipts

Every chat DM carries a 16-bit tag = CRC-16/CCITT-FALSE (poly 0x1021, init 0xFFFF) of the ATAK messageId. The receiving EUD’s automatic delivered/read receipts are converted to Mode 0 Acks echoing that tag; the sender maps the tag back to the original messageId and injects the receipt CoT, producing ATAK’s delivered/read checkmarks end-to-end over RF. These application receipts are independent of the mesh-layer ACKs of section 4.6.

5.5 Contact Publication

Received PLIs are reconstructed with <contact callsign="..." endpoint="*:-1:stcp"/> and a <__group> detail, so ATAK registers the heard station as a messageable contact (chat DM list, send-to pickers) from a single PLI. Outgoing traffic to that contact is intercepted by the plugin’s PreSendProcessor and transmitted over the mesh.

7. Compatibility and Constraints

  • All stations on a channel must run the same plugin wire version (0.12+ mesh framing) and the same modem selection.
  • Mercury DATAC4 limits routed Directs to ~29-byte HBC payloads (Broadcasts ~39 B). All standard messages fit; very large Mode 6 markers may require Broadcast or another modem.
  • Callsigns are limited to 8 ITA2 characters (A–Z, 0–9, hyphen).
  • No encryption is used or permitted; do not transmit sensitive data.
